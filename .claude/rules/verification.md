# Verification

- 실제로 실행한 검사만 "통과"라고 쓴다. 못 한 검사는 못 했다고 보고와 PR에 적는다.
- 검사를 통과시키려고 기준(요구사항 · 테스트 · 검사 스크립트)을 약하게 고치지 않는다.

## 문서 저장소

- 문서를 고친 뒤 `node scripts/check-docs.mjs`를 돌린다. 필수 파일 · 상대 링크 · 표 열 수 · 요구사항 ID · YAML 형식을 본다.
- 이 검사(로컬이든 CI든) 통과는 형식 검사일 뿐이다. 결정과 문장이 맞는지는 doc-editor 정합성 검사나 사람이 읽어서 확인한다.
- 결정을 반영한 뒤에는 doc-editor로 세 문서와 파생 문서의 정합성을 확인하는 것을 권장한다.

## 개발 저장소 (생성 후)

- 버그 수정은 가능하면 재현 테스트를 먼저 추가하거나, 최소한 재현 절차를 적는다.
- 새 기능은 요구사항의 수용 기준(명세서 「상세 / 수용 기준」 열)으로 성공 경로와 주요 실패 경로를 검증한다.
- flaky test를 재실행으로 숨기지 않는다.
- 테스트 전략은 `docs/DEVELOPMENT.md` 「7」, 실행 명령은 같은 문서 「6」을 따른다.
