# Security

## 공통

- secret · token · password · private key를 문서 · 코드 · 이슈 · PR · 커밋 메시지에 넣지 않는다 (NFR-09).
- `.env` 계열 파일 내용을 읽거나 출력하지 않는다. 확인은 "설정됨 / 미설정"까지만 한다.
- **실제 고객 개인정보를 쓰지 않는다.** 이 프로젝트는 모의 데이터로만 개발 · 시연한다. 예시 · 시드 · 이슈 · 스크린샷에 실존 인물의 이름 · 전화번호를 넣지 않는다. 예시 번호는 `010-0000-0000`처럼 가짜임이 분명한 값을 쓴다.
- 법 조항은 설계 근거로만 인용한다. 상업 운영이 아니므로 조문 원문 확인·법무 검토는 하지 않고(결정체크리스트 「법 조문 확인 범위」), "법을 완전히 준수한다"고 쓰지도 않는다.

## 개발 저장소에서 (요구사항 근거)

- 권한은 API에서 검사한다. 화면에서 버튼을 숨기는 것은 권한 검사가 아니다 (NFR-04).
- 인증(매장 로그인 · 근무자 PIN)과 인가(기능별 공용/PIN · 원장 PIN)를 구분한다 (명세서 2장).
- 모든 조회 · 변경은 세션의 매장으로 제한하고, 다른 매장 데이터는 404로 응답한다 (NFR-03).
- 연락처 마스킹은 서버 응답 단계에서 적용한다 (NFR-04).
- 비밀번호 · PIN은 BCrypt 해시로만 저장한다 (NFR-02).
- 입력은 서버에서 다시 검증하고, 출력은 이스케이프한다 (NFR-08). SQL · 경로 · URL을 사용자 입력과 문자열로 이어 붙이지 않는다.
- 로그에 비밀번호 · PIN · 세션 쿠키 · 고객 연락처를 남기지 않는다. 개인정보 접근 기록은 `access_log`에만 남긴다 (NFR-06).
- 새 dependency는 필요성과 유지보수 상태를 확인한 뒤 추가하고, 보안에 영향을 주는 변경은 PR 「영향 범위」에 적는다.
