# Scope Control

작업 중 "같이 고치면 좋아 보이는 것"을 발견해도 범위를 넓히지 않는다.

지금 작업과 무관하면:
1. 문제를 짧게 기록한다 (보고의 「못 고친 것」 또는 별도 이슈 후보).
2. 현재 작업에는 포함하지 않는다.

## 문서 저장소에서 근거 없이 하지 않는 변경

- 결정체크리스트의 결정 열 · `**결정**:` 줄 · `결정 내용` 블록 · `>` 인용 수정
- 요구사항 ID · 결정 항목 번호 재정렬, 우선순위(P1~P3) 변경
- 루트 세 문서의 이동 · 이름 변경 · 절 구조 재작성
- 새 기준 문서 추가 (PRD · 요구사항 정의서처럼 기존 문서와 역할이 겹치는 문서)
- `[제안]` · `[검토 필요]`를 `[확정]`으로 바꾸기
- 기술 스택 범위(명세서 6장 「제약」), 권한 정책(명세서 2장), 데이터 엔티티(명세서 5장) 변경

## 개발 저장소에서 근거 없이 하지 않는 변경

- 폴더 구조 전면 변경, framework/library 교체, 빌드 도구 변경
- dependency 대량 업데이트, formatter 전체 적용, naming 일괄 변경
- API 계약 · DB schema · 권한 정책 변경 (`docs/CONTRACTS.md` 「5. 계약 변경 절차」를 먼저 따른다)
- CI/CD · 배포 대상 변경
