# Keepsy (킵시) — 기획·설계 문서

고객의 취향·사진·메모를 "잘 간직한다"는 뜻의 뷰티샵 CRM, Keepsy의 문서 저장소입니다 (뚝딱랩). 직원 2명 이상 뷰티샵(네일·속눈썹·왁싱·반영구)의 고객 정보를 한 화면에 모으고, 고객별 방문 주기로 다음 방문 기간을 예측해 검토를 거친 메시지 발송과 성과 추적까지 잇는 CRM 웹 서비스입니다.

- 현재 단계: 문서 기획. 애플리케이션 코드는 이 저장소에 두지 않고, 구현은 별도 개발 저장소를 만들어 진행합니다 (아직 만들지 않음).
- 범위: 모의 데이터로 개발·시연까지. 실제 매장 운영(파일럿)과 실제 문자 발송은 하지 않고, 배포 없이 로컬에서 실행합니다 (결정체크리스트 「프로젝트 범위」, A6, A14).

## 상태 표시

| 표시 | 뜻 |
| --- | --- |
| 확정 | 기준 문서(결정체크리스트·명세서·기획서)에 근거가 있음. 기준 문서가 스스로 "제안"으로 적은 것은 확정이 아님 |
| 제안 | 확정된 요구사항에서 끌어낸 설계 초안. 팀 확인 전 |
| 검토 필요 | 정해야 하는데 아직 근거가 없음 |
| 보류 | 결정을 미룸 |
| 제외 | 이번 범위에서 뺌 |

- 결정체크리스트는 결정 열에 `초안 유지` · `변경` · `제외`(E 묶음은 `채택` · `변경` · `제외`)를 씁니다. `미정` · `보류`인 항목은 기준이 아닙니다.
- `docs/` 문서는 항목마다 `[확정]` · `[제안]` · `[검토 필요]`를 붙입니다.

## 요구사항 ID

`FR-<영역>-<번호>`(기능), `NFR-<번호>`(비기능). 영역 코드는 ACC 계정, CUS 고객, RSV 예약, PAY 결제, VIS 방문, PRD 예측, CMP 캠페인, ANL 성과, DSH 대시보드, SCH 기능 검색, SET 설정, I18N 다국어입니다 (명세서 1장). ID는 재정렬하지 않고, 지워진 번호도 비워 둡니다. 이슈 라벨 `area:<영역>`도 같은 코드를 씁니다.

## 미결 사항이 있는 곳

- [기획서.md](./기획서.md) 13장 「미결 사항」: 과금 모델, 사진 저장소, 외부 예약 연동, 유사 서비스 추가 확인
- [요구사항명세서.md](./요구사항명세서.md) 6장 「미결 사항」: 가상 발송 실패 비율, 사진 저장소 제공사
- [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md) 9장 「남은 결정」: Spring Boot·Node.js 버전, 패키지 이름, 귀속 발송 ID 등 구현 전에 정할 것
- 법 조문 최종 확인은 상업 운영이 아니므로 이번 범위에서 하지 않습니다 (결정체크리스트 「법 조문 확인 범위」).
